## Capabilities

**DSSAT Crop Simulation Agent**
- Simulate crop yields for 18 different crops: Maize, Soybean, Wheat, Rice, Sorghum, Millet, Dry Bean, Peanut, Sugarcane, Sunflower, Tomato, Potato, Pepper, Cabbage, Cotton, Barley, Chickpea, Pigeon Pea
- Soil profile management: browse, create, edit, estimate from texture
- Cultivar browser with ecotype parameters
- DSSAT code reference for planting methods, fertilizer materials, irrigation methods, and more

### Experiment Types

Choose by the user's intent. The five types differ along two axes:
**how many locations** (one point vs many) and **how the protocols
relate** (one protocol vs N alternatives vs a swept range).

| Type           | Locations           | Protocols                                  |
|----------------|---------------------|--------------------------------------------|
| `single`       | 1 point             | 1                                          |
| `ensemble`     | 1 point             | N independently-configured alternatives    |
| `sensitivity`  | 1 point             | N generated by sweeping ONE variable axis  |
| `monte_carlo`  | N grid points (region-sampled) | 1 shared template          |
| `batch`        | M explicit points/areas        | N protocols (matrix)       |

#### `single` — one specific scenario at one specific location

Use when the user names a **point** location (a farm, a field, a town,
or explicit lat/lon) and ONE set of conditions. State-level / county-
wide / regional language signals one of the multi-location types
instead.

- "Simulate maize at my farm at 33.0, -86.5 planted March 15"
- "What yield would I get with corn planted May 1 at this Auburn, AL field?"
- "Run a wheat simulation with these fertilizer settings at my Cullman test plot"
- "How many days to maturity for rice planted on April 1 at this paddy?"
- "What happens if I plant soybeans on April 20 at my farm in Macon, GA?"
- "Predict corn yield at my farm with 7 plants/m² and 120 kg N/ha"

Signal words: "simulate", "run", "predict" + ONE scenario. "my farm",
"my field", "this site", "at this location", explicit lat/lon, or a
city/town as a single point. **No** comparison language ("vs",
"compare", "best", "sweep", "expected across").

#### `ensemble` — compare N alternatives at one location

Use when the user wants to compare a discrete set of independently-
configured protocols at the same site. Each protocol can vary any
combination of parameters (fertilizer, irrigation, planting date,
cultivar, tillage, etc.).

- "Compare three fertilizer plans at my Cullman site"
- "Test no-till vs conventional tillage on my farm"
- "Try three irrigation strategies for my wheat field"
- "Which cultivar fits my soybean farm — IB0001, IB0002, or IB0003?"
- "Should I irrigate my corn?" (irrigated vs rainfed = 2-protocol ensemble)
- "Run two protocols at my farm: high N (120 kg/ha) vs low N (40 kg/ha)"
- "Compare planting March 1 vs April 1 vs May 1 at my Auburn site"
  (discrete dates → ensemble; if the user says "sweep April-May" → sensitivity)

Signal words: "compare", "vs", "versus", "best", "optimal",
"recommend", "should I", "test strategies", "try different",
**discrete** named alternatives at the same site.

NOTE: You don't have to invent specific treatment definitions if the
user is vague. Just set `experiment_type: "ensemble"` and put the
user's comparison intent in `additional_instructions`
(e.g. "compare irrigation strategies", "find the best fertilizer
plan"). The simulation agent will auto-generate treatments. If the
user does specify exact values, include them so the system knows the
discrete set.

#### `sensitivity` — sweep ONE variable over a range at one location

Use when the user wants to **vary** a single parameter across a
continuous range or a Cartesian set of step counts. Same site, same
weather, but the swept axis (planting date / population / row spacing
OR cultivar list OR one management practice's amount × applications ×
gap-days) generates N treatments via the Cartesian-within-category
generator.

- "How sensitive is corn yield to planting date at my farm?"
- "Sweep planting date from April 1 to May 15 in 2-week steps for soybean"
- "How does yield change if I vary nitrogen from 100-200 kg/ha in 5 steps?"
- "Run a sensitivity analysis on plant population from 5 to 9 plants/m² for maize"
- "What if I varied row spacing from 50 to 100 cm in 6 steps?"
- "Test cultivars IB0001, IB0002, IB0003, IB0004 at my field"
  (multi-select cultivar list = sensitivity's cultivar category)
- "How sensitive is yield to fertilizer rate?"

Signal words: "sweep", "vary", "sensitive to", "sensitivity",
"how does X affect", "from X to Y in N steps", multi-select cultivar
lists, ranged-not-discrete values for one parameter.

Ensemble vs sensitivity rule of thumb: ensemble has hand-defined,
heterogeneous protocols (each varies different things); sensitivity
sweeps ONE category along an axis or list. If the user names exactly 2-3
discrete values for one parameter and uses "compare", route to
ensemble. If they say "sweep" / "vary" / "sensitive" or give a
range + step count, route to sensitivity.

#### `monte_carlo` — spatial uncertainty across a region

Use when the user asks about expected yields, variability, or risk
across a geographic **area** (state, county, district, circle, bbox)
rather than a specific point. The system samples N grid points within
the region and runs the same template protocol at each.

- "What is the expected yield of corn across Alabama?"
- "How does maize yield vary across Cullman County?"
- "What's the yield range for wheat in the southeast?"
- "How reliable is corn production in this region?"
- "Run a spatial analysis of soybean yield in Georgia"
- "What are the yield confidence intervals for rice in Louisiana?"
- "Estimate county-wide corn production"
- "How risky is it to plant wheat in this area?"
- "Sample 50 random points across this bbox and run corn"

Signal words: region/area scope (state, county, district, parish);
"expected", "average across", "yield range", "spatial", "regional",
"uncertainty", "confidence", "variability", "reliable", "risk",
"how does yield vary from place to place".

#### `batch` — explicit (location × protocol) matrix

Use when the user wants to run the same set of protocols at multiple
**named/explicit** locations (a farm portfolio, a list of cities, every
county in a state). Cardinality is M × N: every checked cell of the
matrix becomes one DSSAT run.

- "Run two fertilizer plans at three of my farms — site A, B, and C"
- "Compare four management protocols across my five test sites"
- "Test high vs low N at locations Auburn, Huntsville, and Mobile"
- "Run my standard protocol at all 7 of my farms"
- "Apply both my high-N and low-N protocols at each of these 4 fields"
- "Simulate corn at these 5 cities with two cultivars each"
- "Run a simulation for corn at every county in Alabama"  (admin-area batch)
- "Compare maize yield across counties in the Southeast" (admin-area batch)

Signal words: "at locations X, Y, Z", "across my N farms", "at each of
these sites", "run at all", "every county / every state", explicit
multi-site list, "matrix", "(M × N)" cardinality language.

Configuration:
- `sub_experiment_type` controls what runs at each location (default
  `"single"`; can also be `"ensemble"` or `"monte_carlo"`).
- For point-list batches (named sites): pass `locations: [...]` with
  point shapes.
- For admin-area batches (every county / every state): set
  `location_selection_mode: "admin_boundary"`,
  `admin_parent: "<region>"`, and `admin_child_level: "admin2"` for
  counties or `"admin1"` for states.

Batch vs Monte Carlo: batch is **explicit, named locations** the user
listed (or every admin unit they named); Monte Carlo is **statistical
sampling** within a region for uncertainty / variability framing. If
the user says "test at these 5 fields" → batch; "what's the yield
range across the region" → Monte Carlo.

### Disambiguation

| Query | Type | Reasoning |
|---|---|---|
| "What yield can I expect from corn in Alabama?" | Monte Carlo | "Alabama" = region, "expect" wants a distribution |
| "What yield at my Alabama farm planted May 1?" | Single | "my farm" = specific point |
| "How does planting date affect yield at my Cullman field?" | Ensemble *or* Sensitivity | Discrete dates → ensemble; range / sweep → sensitivity |
| "Sweep planting date April 1 → May 15 at my farm" | Sensitivity | "sweep" + range |
| "Compare March 1, April 1, May 1 at my farm" | Ensemble | 3 discrete named dates |
| "How does yield change across Cullman County?" | Monte Carlo | Spatial variation within one area |
| "Should I irrigate my corn?" | Ensemble | 2-protocol comparison: irrigated vs rainfed |
| "Is corn a good crop for this region?" | Monte Carlo | Regional assessment, spatial sampling |
| "Compare corn yield across all counties in Alabama" | Batch | One run PER county (every named admin unit) |
| "Run corn at every county in Alabama" | Batch | Independent run per location |
| "What yields can my 4 farms expect?" | Batch | Explicit multi-site list |
| "Run my high-N and low-N protocols at every one of my 4 farms" | Batch | M=4 × N=2 = 8 cells |
| "How sensitive is yield to row spacing?" | Sensitivity | Single-axis sweep |
| "Test 50 sample points within this bbox" | Monte Carlo | Random sampling for uncertainty |
| "Run multiple simulations for corn" | Clarify | Ambiguous — varying what? Locations (batch / MC) or protocols (ensemble / sensitivity)? |
